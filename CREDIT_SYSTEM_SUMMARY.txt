DATABASE SCHEMA CHANGES
================================================================================

users table (modified):
+ credits INT DEFAULT 0
+ gamesPlayed INT DEFAULT 0

user_credit_transactions table (new):
- id (PK)
- userId (FK → users.id)
- amount INT
- balanceBefore INT
- balanceAfter INT
- type ENUM('top_up', 'game_deduction', 'admin_add', 'admin_subtract', 'counter_reset')
- notes TEXT (nullable)
- adminId INT (nullable)

================================================================================
BUSINESS LOGIC
================================================================================

Game Start Flow:
1. User clicks "Start Game" button
2. Backend checks if user.credits > 0
3. If credits = 0:
   - Emit "credit-exhausted" event
   - Throw error "No credits remaining"
   - Frontend shows error toast
   - Start button stays disabled
4. If credits > 0:
   - Deduct 1 credit (credits - 1)
   - Increment gamesPlayed (gamesPlayed + 1)
   - Create transaction record (type: game_deduction)
   - Start the game
   - Emit "game-started" with new values
   - Frontend updates UI

Add Credits Flow:
1. Admin clicks Add Credits (🪙)
2. Enters amount and notes
3. Backend adds credits to user.credits
4. Creates transaction record (type: admin_add)
5. Records admin who added credits
6. Returns updated user object
7. Frontend refreshes user list

Reset Counter Flow:
1. Admin clicks Reset Counter (🔄)
2. Confirms action
3. Backend sets user.gamesPlayed = 0
4. Credits remain unchanged
5. Creates transaction record (type: counter_reset)
6. Returns updated user object
7. Frontend refreshes user list
